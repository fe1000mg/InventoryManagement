## これは何か

毎日の献立にかかる食費を記録・集計する Web アプリ。もとはエクセル（`../../献立コスト計算.xlsx`、リポジトリの外の「生活」フォルダにある）で作ったものを Web 化した。

- 公開：GitHub Pages（`https://fe1000mg.github.io/InventoryManagement/kondate/`）
- 構成は在庫ノート（リポジトリ直下の `index.html` + `gas/Code.gs`）と同じ考え方
  - `kondate/index.html`：画面と計算のすべて（素の HTML/CSS/JS、外部ライブラリなし。グラフも手書きの SVG）
  - `kondate/gas/Code.gs`：Google Apps Script。スプレッドシートへの読み書き API
  - `kondate/README.md`：ユーザー向けのセットアップ手順
- スプレッドシート未接続のときはブラウザの localStorage に保存（お試しモード。設定タブからサンプルデータを入れられる）

## データ（スプレッドシートのシート ＝ API のテーブル名）

| テーブル | シート名 | 列 |
|---|---|---|
| purchases | 買い物 | id, date, name, qty, unit, price, updatedAt |
| cooks | 料理記録 | id, date, slot, dish, ingredient, qty, updatedAt |
| recipes | レシピ | id, dish, ingredient, qty, unit, updatedAt |
| plans | 献立予定 | id（= `日付|区分`）, date, slot, dish1, dish2, dish3, budget, updatedAt |
| holidays | 休日 | id（= 日付）, date, updatedAt |
| aliases | 表記ゆれ辞書 | id, alias, name, updatedAt |
| seedPrices | 初期単価 | id, name, unit, price, updatedAt, stock |

- 日付は `YYYY-MM-DD` の文字列。GAS 側で文字列書式にし、Date 型が来ても文字列に直して返す
- API：`GET ?action=all`（全テーブル）/ `GET ?action=ping`（`{ok:true, app:'kondate'}`）
- `POST`（`Content-Type: text/plain`、在庫ノートと同じ）：`upsert {table, rows}` / `delete {table, ids}` / `replaceDish {dish, rows}`（レシピを料理ごと置き換え）
- localStorage のキー：`kondate-sheet-url`, `kondate-data`, `kondate-week-start`, `kondate-shop-check`（在庫ノートの `sheet-webapp-url` とはぶつからない名前にしてある）

## 計算ルール（エクセル版と同じ。変えるときは両方の整合に注意）

- **食材名の正規化**：前後の空白・全角空白を除去 → 表記ゆれ辞書（alias → name）で読み替え。買い物は入力のまま保存し、集計時に正規化
- **平均単価（プール）**：同じ食材は買った量・金額を合算し、単価 ＝ 金額合計 ÷ 量合計
- **料理の費用**：使った量 × 平均単価
- **食事区分**：土日・休日（holidays に入っている日）は「朝/昼/晩」、平日は「てつ朝/ぬん朝/てつ昼/ぬん昼/晩」。週の棒グラフは「朝/昼」を含むかで朝・昼・晩にまとめる
- **料理1回**：日付＋区分＋料理名のまとまり。料理ごとの平均費用・平均材料量はこの単位で出す
- **予定金額**：予算の入力があればそれ。なければ予定の料理①〜③それぞれについて「レシピがあればレシピの費用、なければ過去の平均費用」を足す。どれも不明なら空
- **判定**：①の料理名が実際の料理に含まれれば「○」、記録があって違えば「変更」、記録がなければ「未記録」
- **差額**：予定金額と実際の金額の両方がある枠だけ
- **買い物リスト**：表示中の週で「まだ料理の記録がない予定の枠」だけを対象に、料理ごとに「レシピがあればレシピの量、なければ過去の平均量」を合計 → 必要量 − 家の残り（買った量 − 使った量、マイナスは0）＝ 買う量。材料不明の料理は別に表示。パック単位の切り上げはしない（ユーザーの希望）
- 料理の記録では、食材は「買い物に入れたもの」か「設定タブで登録したもの（seedPrices）」からしか選べない（表記ゆれ防止）。在庫ノートとはまだ連携していないので、在庫ノートにしかない品目は選べない（ユーザーには伝えてある）
- **初期単価（家にあるもの）**：食材に買い物の記録が1件もないとき、設定タブの「食材の登録」の単価を使う。買い物の記録が1件でもあれば、そちらの平均単価が自動的に優先され、初期単価は無視される（`recompute()`内 `e.buyQty > 0` で判定）。単価は空でもよく、その場合は「料理を記録」で選べるだけになり、費用は「単価不明」扱い
- **棚卸（今ある量）**：seedPrices の `stock` は「残り」の計算に毎回そのまま加算される固定の下駄（`e.remain = buyQty - used + stock`）。履歴ではなく今のスナップショットなので、ずれたらその数字を書き換えるだけで直せる。買い物の実績が増えても stock の値は減らない点に注意（在庫ノートのような本当の棚卸ではない簡易版）

- 「初期単価」機能を追加済み：買い物の記録がまだない食材でも、設定タブで単価を先に登録しておけば費用計算に使われる（買い物の記録が1件でもできれば、そちらの実績の平均単価に自動で切り替わる）
  - 在庫品目.xlsx（`../在庫品目.xlsx`）の「食材」シートの最安値から30件を初期値として取り込んだ。元データが「基準数量あたりの価格」のため `単価 ÷ 基準数量` で1単位あたりに変換している
  - 卵・オートミール・豆腐の3件は元データの単位があいまいだったため、ユーザーに実際のパックサイズ・内容量を確認してから入力した（卵=10個入り、オートミール=1000g袋、豆腐=300g/丁）
- seedPrices に `stock`（今ある量・簡易棚卸）を追加済み。**GAS再デプロイ後、既存の「初期単価」シートのF1セルに手動で見出し `stock` を追加する必要がある**（既存列を壊さないよう末尾に追加したため、シート側は自動で増えない）。これをやらないと「今ある量」の値が保存されても読み込み側で無視される
- 「料理を記録」で買い物していない食材も選べるようにしたい、という要望に対しては、ユーザーに選んでもらって**在庫ノートとは連携せず、献立ノート単体（seedPrices の拡張）で対応する**ことに決めた。在庫ノートの品目名を読み込む・フル連携する案も出したが、今回は見送り
